# Правила репозитория

1. Перед изменениями прочитай README.md, spec/product/ и spec/tech/.
2. До изменения кода обнови спецификацию затронутого поведения и способ его проверки, опиши решение и разбей работу на задачи с ответственными и критериями приёмки. Разделяй реализованное поведение, подтверждённые проверки и планы. Текущие задачи — в spec/tech/tasks.md.
3. После изменений запусти `uv run python manage.py check` и `uv run python manage.py test tests`. При изменении запуска проверь uv и Docker Compose.
4. Обнови CHANGE_HISTORY.md: что изменилось, какие проверки выполнены, их фактические результаты и оставшиеся ограничения. Не записывай невыполненные проверки как успешные.
5. Проверь Git diff. Сохраняй чужие изменения, не добавляй окружения, кеши, секреты и файлы IDE в репозиторий.
6. Интерфейс проверь в браузере по spec/product/scenarios.md. Benchmark запускай при изменении реализованного RAG; на КТ №1 RAG ещё не подключён. Результаты и ограничения фиксируй в spec/product/kt1.md и CHANGE_HISTORY.md. Исторические проверки не заменяют проверку новой версии.

Бэкенд и интерфейс разрабатываются в одном Django-проекте. Роли команды описаны в README.md.
