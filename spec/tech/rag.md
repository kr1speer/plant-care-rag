# RAG: корпус, поиск и benchmark

Документ описывает, откуда берутся данные, как они хранятся и режутся на фрагменты, как работает поиск BM25 и как проверяется качество. Ответственный: Антон.

## 1. Путь запроса

```
вопрос пользователя
  → токенизация вопроса
  → BM25-поиск по фрагментам корпуса (top-5)
  → промпт для LLM: инструкция + найденные фрагменты + вопрос
  → ответ LLM + список источников
```

### Как собирались статьи

Текст получен через API Википедии в виде обычного текста. Из каждой статьи оставлены вступление и разделы об описании, уходе, размножении, болезнях и вредителях. Удалены разделы «Примечания», «Литература», «Ссылки», таксономия, синонимы, палеонтология и история. Объём одной статьи ограничен примерно 5500 символами, чтобы длинные статьи не доминировали в поиске.

## 3. Формат хранения

Корпус лежит в `data/corpus/`, один документ в одном файле `.md`. Имя файла — `NN_slug.md`, где `NN` — порядковый номер, а `slug` — транслит названия.

Структура файла:

```markdown
# Название статьи

Источник: <URL статьи>
Версия статьи: <revision id Википедии>
Лицензия: CC BY-SA 4.0 ...

---

Вступление статьи...

## Раздел (например, «Культивирование»)
Текст раздела...
```

Всё, что выше линии `---`, — метаданные. В индекс они не попадают, но используются для вывода источника пользователю. Всё, что ниже, — текст для поиска.

## 4. Разбиение на фрагменты (chunking)

1. Документ делится по заголовкам `##` и `###`. Каждый раздел становится отдельным фрагментом, вступление — тоже.
2. Если раздел длиннее 1000 символов, он делится по абзацам на куски примерно по 800 символов. Соседние куски перекрываются на один абзац.
3. Фрагменты короче 100 символов склеиваются со следующим.
4. В начало каждого фрагмента добавляется название статьи и раздела, например `Фаленопсис. Фаленопсис в культуре.`. Благодаря этому вопрос «как поливать фиалку» находит раздел «Полив» именно статьи о сенполии.

Каждый фрагмент хранится так:

```json
{"chunk_id": "10_falenopsis#2", "doc": "10_falenopsis.md", "title": "Фаленопсис", "section": "Фаленопсис в культуре", "url": "https://ru.wikipedia.org/wiki/Фаленопсис", "text": "..."}
```

## 5. Поиск BM25

- **Библиотека:** `rank_bm25` (`BM25Okapi`), параметры по умолчанию `k1 = 1.5`, `b = 0.75`.
- **Токенизация:** нижний регистр, замена «ё» на «е», выделение слов регулярным выражением `\w+`, удаление русских стоп-слов.
- **Нормализация слов:** стемминг `snowballstemmer` (русский), чтобы «полив», «поливать» и «поливают» совпадали. Если качество окажется низким, можно попробовать лемматизацию `pymorphy3`.
- **Результат:** top-5 фрагментов с оценкой BM25.
- **Порог:** если лучшая оценка ниже порога (подбирается на benchmark), считаем, что ответа в корпусе нет, и LLM отвечает «Не нашёл информации в базе».
- **Индекс** строится при запуске приложения из `data/corpus/`. При 28 документах это занимает доли секунды, отдельное хранилище не нужно.

## 6. Промпт для LLM

```
Ты помощник по уходу за комнатными растениями.
Отвечай только на основе фрагментов ниже. Если в них нет ответа, скажи, что не нашёл информации.
Отвечай кратко, по-русски. В конце укажи номера использованных фрагментов.

Фрагменты:
[1] <title> — <section>: <text>
...

Вопрос: <вопрос пользователя>
```

Пользователю показываются ответ и список источников (название статьи и ссылка) по использованным фрагментам.

## 7. Benchmark

### Формат

Файл `benchmark/questions.jsonl`, по одному вопросу JSON на строку:

| Поле | Описание |
|------|----------|
| `id` | Идентификатор вопроса (`q01`) |
| `question` | Вопрос так, как его задал бы пользователь |
| `expected_answer` | Эталонный ответ, взятый из текста корпуса |
| `relevant_docs` | Файлы корпуса, где есть ответ (пусто — ответа в корпусе нет) |
| `type` | `fact`, `how-to`, `problem` или `out-of-scope` |

### Примеры вопросов

| id | Вопрос | Ожидаемый ответ | Документ |
|----|--------|-----------------|----------|
| q01 | Какая температура нужна фикусу Бенджамина летом и зимой? | Летом 25–30 °C, зимой 16–20 °C, не ниже 14 °C | `03_fikus-benjamina.md` |
| q02 | Как часто пересаживать орхидею фаленопсис? | Раз в год, после цветения | `10_falenopsis.md` |
| q03 | В какой субстрат сажать фаленопсис? | Крупные кусочки сосновой коры, дренаж из керамзита | `10_falenopsis.md` |
| q04 | Как правильно поливать фиалку (сенполию)? | По мере подсыхания верхнего слоя, по краю горшка, не на листья, не холодной водой | `11_senpoliya.md` |
| q05 | Какой горшок нужен для взрослой фиалки? | Около 9 см, в 3 раза меньше розетки | `11_senpoliya.md` |
| q06 | Почему у сансевиерии гниют корни? | Слишком частый полив, грунт должен просыхать | `05_sansevieriya.md` |
| q07 | Как размножить сансевиерию? | Делением корневищ или частями листа от 5 см, подсушив | `05_sansevieriya.md` |
| q08 | Почему желтеют листья и что такое хлороз? | Нехватка железа, магния, азота, плохой дренаж, переувлажнение | `27_hloroz.md` |
| q09 | Почему у монстеры мелкие листья без прорезей? | Не хватает света | `02_monstera.md` |
| q10 | Почему после опрыскивания фикуса остаются белые пятна? | Жёсткая вода, нужна мягкая | `03_fikus-benjamina.md` |
| q11 | Как вырастить помидоры на балконе? | Ответа нет, приложение должно это сказать | — |

К контрольной точке 2 набор расширяется до 25–30 вопросов: минимум по одному на каждое растение и вредителя плюс 3–5 вопросов вне темы.

### Метрики

1. **Hit@5 (поиск):** доля вопросов, для которых хотя бы один фрагмент из `relevant_docs` попал в top-5. Считается автоматически, без LLM.
2. **MRR (поиск):** среднее значение `1 / позиция` первого релевантного фрагмента.
3. **Корректность ответа:** ответ сравнивается с `expected_answer` по шкале 0 / 0.5 / 1. Оценку ставит человек или LLM-судья с отдельным промптом.
4. **Отказ вне темы:** доля вопросов `out-of-scope`, на которые приложение честно ответило «не нашёл».

### Запуск и хранение результатов

Скрипт `benchmark/run.py` (будет написан на этапе RAG) проходит по всем вопросам, сохраняет найденные фрагменты, ответы и метрики в `benchmark/results/YYYY-MM-DD.json` и печатает сводку. Результаты коммитятся в Git, чтобы на защите было видно, как менялось качество.
