## Решения исполнения

- Работа продолжается в существующей ветке `issue-10`; незавершённые изменения LICENSE сохраняются. Новая копия checkout не создаётся, чтобы правки оставались в рабочей области пользователя.
- Документы обновлены до кода. Источник требований — слайды 4–12 занятия 1 и утверждённый в чате план.
- До реализации UI/API добавить и запустить проверки нового поведения, затем повторить их после реализации.
- Исправления готовятся локально; push/merge и сообщения преподавателю не выполняются без отдельного поручения.

## Итог исполнения

T1–T6 выполнены локально. Реализация зафиксирована коммитом `6e5e295`. Проверены 18 Django-тестов и настоящий Chromium для uv, Compose и чистого локального клона. Независимое ревью не выявило замечаний. T7 подготовлен в части черновика сдачи; публикация, проверка опубликованного SHA и личный запуск участников остаются внешними шагами.

## КТ №2: поиск BM25 и benchmark

Первая часть КТ №2 — собственный BM25-поиск и benchmark без LLM. Требования курса: самостоятельная реализация индекса (`rank_bm25` и другие поисковые библиотеки запрещены), корпус из 30 документов D01–D30, 10 обычных вопросов (не меньше 3 релевантных документов и эталон у каждого, разные темы) и 5 ловушек с ожидаемым отказом «В документах нет этой информации», метрики Recall@k и MRR по обычным вопросам, Accuracy из 10, Correct Rejection Rate из 5, `k = 3`. Интерфейс и API `/ask` в этой части не меняются. Решение — [rag.md](rag.md).

### Решения исполнения первой части (№12)

- Работа идёт в ветке `issue-12`; ветка отправляется в `origin`, PR создаёт и сливает автор. Merge агентом не выполняется.
- Стемминг — зависимость `snowballstemmer`; стоп-слова и BM25 — собственный код в `app/rag/`.
- `app/rag/` не зависит от Django; Docker-образ получает весь `data/`, чтобы тесты поиска работали в контейнере.
- В первой части результаты получены в режиме `--retrieval-only`. Команды полного прогона после №13 приведены в README.
