# Архитектура

## Путь запроса

```text
Интерфейс (будущий Django-интерфейс)
    → POST /ask (Django API)
    → BM25 (поиск релевантных фрагментов)
    → LLM (вопрос + инструкция + найденный контекст)
    → JSON: ответ + источники
    → интерфейс: ответ + ссылки
```

Интерфейс и API планируются в одном Django-проекте. API проверяет вопрос и вызывает слой ответа. BM25 будет отвечать за поиск фрагментов, LLM — за ответ по переданному контексту. Интерфейс, продуктовые спецификации, описание RAG, корпус и benchmark готовят коллеги.

## Реализовано на контрольной точке 1

`POST /ask` проверяет JSON и вызывает функцию сервиса в `app/assistant/services.py`, которая возвращает постоянную заглушку. Интерфейс, BM25 и LLM не реализованы. Нет внешних запросов, ключей, моделей БД, аккаунтов или миграций. Список источников пуст. У главной страницы `/` нет обработчика.

Конфигурация Django находится в `app/config/`, API и слой ответа — в `app/assistant/`. Каталоги spec/product/ и benchmark/ сохранены с .gitkeep для работы коллег.

## Контракт API

Путь — `POST /ask` без завершающего слеша. Content-Type: application/json. Тело — JSON-объект с полем question: непустая строка после удаления пробелов по краям. Дополнительные поля игнорируются.

```json
{"question": "Как поливать монстеру?"}
```

Ответ HTTP 200:

```json
{
  "answer": "Тестовый ответ. Поиск BM25 и LLM пока не подключены.",
  "sources": []
}
```

Ошибки содержат строковое поле error: HTTP 400 для некорректного JSON или вопроса, HTTP 415 для неверного Content-Type, HTTP 405 для неподдерживаемого метода (Allow: POST), HTTP 403 при ошибке CSRF. Неизвестные пути возвращают 404.

CSRF-защита сохраняется. Для получения cookie выполните `GET /ask`: он возвращает 405, но устанавливает csrftoken. Затем отправьте POST с этой cookie и заголовком X-CSRFToken. Отдельная страница или эндпоинт для получения токена не нужны. Пример curl приведён в README.

## Запуск и проверки

Python 3.13, Django 5.2, зависимости в pyproject.toml и uv.lock. Локально: `uv run python manage.py runserver`. Контейнер: `docker compose up --build`, тот же lock-файл. API доступен по адресу `http://localhost:8000/ask`.

Это конфигурация локальной разработки: DEBUG включён, Django runserver, доступ в Compose опубликован только на loopback. Для развёртывания нужен отдельный проектный этап.

Проверки: Django system check, API-тесты и запрос curl при обоих способах запуска.
