Браузер проверил: три ответа и реальные ссылки; ввод с клавиатуры; неподдерживаемые вопросы; пробелы без запроса; один запрос при повторной отправке; скрытие прошлых карточек; HTTP 403/500; некорректный JSON и структуру ответа; отключение сети и восстановление; вывод HTML как текста и блокировку javascript-ссылки; отсутствие необработанных JS-ошибок; ширины 375 и 1280 px без горизонтальной прокрутки. Ошибки HTTP/сети подставляются тестом намеренно.

Скриншоты просмотрены: [uv 375 px](evidence/uv-mobile.png), [uv 1280 px](evidence/uv-desktop.png), [Compose 375 px](evidence/compose-mobile.png), [Compose 1280 px](evidence/compose-desktop.png).

Один запуск браузерного инструмента в чистом клоне завершился кодом 139 без вывода; повторный запуск с диагностикой Playwright прошёл полностью. Причина аварии инструмента не установлена; она не скрыта за успешным повтором.

Окружение: uv — Python 3.13.13, Django 5.2.18; контейнер — Python 3.13.17, Django 5.2.18, тот же uv.lock. Chromium установлен через Playwright 1.64.1 во временный каталог. В WSL использован существующий Windows-клиент Docker Desktop с явным путём к compose.yaml; Linux-обёртка без WSL-интеграции не работала. Для Chromium три недостающие библиотеки загружены и распакованы в /tmp без изменения системы. Первичная загрузка зависимостей внутри песочницы завершилась ошибкой DNS; повторная разрешённая загрузка и фактические проверки успешны.

Команды запуска тестов — в README. Во время приёмки использовались `UV_CACHE_DIR=/tmp/kt1-uv-cache`, `PLAYWRIGHT_BROWSERS_PATH=/tmp/kt1-browsers`, `NODE_PATH=/tmp/kt1-browser/node_modules` и временный `LD_LIBRARY_PATH`. Они относятся к среде проверки, не к требованиям приложения.
