# Сценарии

## Демонстрация КТ №1: согласованное поведение

1. Пользователь запускает проект по README и открывает `/`.
2. Видит подпись «Демонстрационная версия: BM25 и LLM не подключены», поле с подписью и три примера:
   - Почему у монстеры мелкие листья без прорезей?
   - Какая температура нужна фикусу Бенджамина летом и зимой?
   - Когда и как пересаживать орхидею фаленопсис?
3. Выбирает пример (он заполняет поле) и нажимает «Спросить».
4. Интерфейс скрывает прошлый результат, показывает ожидание и блокирует повторную отправку. Отправляется один `POST /ask` с JSON и CSRF-токеном.
5. Сервер сопоставляет вопрос с подготовленными примерами. Нормализация: регистр, пробелы, ё/е и завершающие `?!.`. Подстроки не используются.
6. Интерфейс показывает ответ, название статьи, точный фрагмент и ссылку. Повторный вопрос заменяет результат.

| Пример | Ожидаемый смысл ответа | Корпус |
|---|---|---|
| Монстера | Мелкие листья без прорезей связаны с недостатком света | `02_monstera.md` |
| Фикус | Летом 25–30 °C, зимой 16–20 °C, не ниже 14 °C | `03_fikus-benjamina.md` |
| Фаленопсис | Пересадка раз в год после цветения; крупные кусочки сосновой коры | `10_falenopsis.md` |

## Неподдерживаемый вопрос

HTTP 200, `sources: []`, ответ: «Это демонстрационная версия. Выберите один из трёх примеров вопросов. Поиск по корпусу пока не подключён».

Проверочные вопросы: «Как поливать орхидею?», «Когда пересаживать фикус?», «Как вырастить помидоры на балконе?». Они не должны получать чужой ответ. Это ограничение демонстрации, а не результат BM25.

## Ввод, ожидание и ошибки

- Пустой вопрос и пробелы не отправляются; пользователь видит просьбу ввести вопрос.
- Пока запрос выполняется, повторная отправка не создаёт новый запрос. Поле вопроса сохраняется, прошлые карточки скрыты.
- При HTTP-ошибке, ошибке сети или некорректном JSON/контракте показывается понятная ошибка; кнопка снова доступна, введённый вопрос остаётся.
- Ответы и фрагменты выводятся как текст. Ссылки только HTTP/HTTPS, новая вкладка с `noopener noreferrer`.
- Формой можно пользоваться с клавиатуры. Изменение состояния объявляется через live-region. На ширине 375 и 1280 px нет горизонтальной прокрутки.

Проверка: браузерный проход всех ветвей при запуске через uv и Compose; результаты сохраняются в [КТ №1](kt1.md), автоматические проверки — в `tests/`.

## Будущий основной сценарий RAG (план следующего этапа)

Вопрос → поиск BM25 → релевантные фрагменты → LLM → ответ и использованные источники. Если подходящих фрагментов нет, приложение показывает «Не удалось найти ответ в базе статей» и не вызывает LLM. На КТ №1 работающий RAG не требуется.
